# 小搭推荐与点评统一契约 V1

## 目标

小搭是“审美在线、懂搭配、熟悉用户衣橱，说话自然、有判断但不过度点评的朋友型私人穿搭顾问”。推荐理由与详情点评必须像同一个人围绕同一身衣服继续说话，而不是两个独立生成器。

本契约只改变展示与解释层。Scene Evidence V4 的资格、评分、排序、候选生成和产品比例均保持不变。

## 语言原则

- 以用户穿上这身后的整体感受为中心，不以算法字段为主语。
- 先给判断，再用具体衣物关系解释判断。
- 优先说明搭配里最值得说的一件事；没有强洞察时诚实地说它简单、日常、省心。
- Today 负责一句话说清主要价值；Detail 沿同一主洞察多解释一层，可选建议必须有事实增量。
- 不输出“视觉重量、色块、结构完整度、主体连起来、颜色不会断开”等算法中文。
- 不承诺显瘦、显高、显腿长、显白、高级、性感、修饰身材、舒适、透气、保暖、柔软等未被事实授权的效果。

## Style Insight 数据契约

`xiaoda-style-insight-v1` 位于既有推荐事实与最终自然语言之间：

1. 读取 Presentation Fact Model 中的逐件衣物事实、关系和 Scene Eligibility 证据。
2. 只投影既有 `aestheticEvaluation.evidence` 的正向或中性关系，不重新计算审美分、不改变排名。
3. 生成 `primary`、`secondary`、`optional` 三档洞察。
4. Today 与 Detail 均使用同一个 `primary.code`；Detail 不得切换到另一条无关理由。

每条洞察至少包含：主观察、支撑关系、对用户的意义、整体结果、主体衣物、事实来源、允许的审美推断和禁止的效果承诺。

## 排序规则

洞察按以下结构化因素排序：

- 事实是否存在；
- 关系强度；
- 对用户是否有决策价值；
- 相比衣物名称是否提供新增信息；
- 是否针对当前这身衣服；
- 与当前场景的相关性；
- 能否自然地说成人话。

图案主次、设计重点、亮色与中性色支撑、明确的松紧或长短关系通常优先。普通同色、相邻色、风格一致其次。只有基础品类事实时使用简单日常兜底，不制造“高级”“显瘦”等结论。

## 推断边界

- Level 1：直接事实，如品类、颜色、印花、版型、长度、鞋型。
- Level 2：有既有证据支持的关系，如印花与纯色主次、同色呼应、松紧对比、长短层次、正式程度接近。
- Level 3：受控审美推断，如清爽、简洁、自然、有重点、不会太乱、利落、得体、有层次。必须能回溯到 Level 1/2。
- Level 4：身体、材质感受、身份或价值判断，如显瘦、显高、舒适、高级。默认禁止。

## AI Detail 输入与输出

提示词输入只包含脱敏后的逐件衣物事实、场景/真实天气、审美关系、Today 理由和 Style Insight。原始衣物 ID 经过哈希，不传图片地址、用户身份或内部数据库字段。

模型只输出：

```json
{
  "overallComment": "40–120 字，同一主洞察的深入解释",
  "advice": "0–80 字；没有明确增量时为空字符串"
}
```

服务端校验事实边界、人设、算法中文、与 Today 的重复度、信息增量和主洞察连续性。任何一项失败都回退到同一 Style Insight 的规则点评。

## 回归门槛

- Scene Evidence V4 文件不得改动。
- 所有 Today / Detail 文案必须通过事实、人设与自然度门禁。
- 夹具覆盖上下装、连衣裙、外套、鞋、可选配饰、四场景、缺失属性、弱事实、多洞察和未来单品类型。
- 线上验收覆盖四场景各两批、共 64 条 Today 最终 UI 文案，以及至少 8 条 Detail 最终 AI 点评。
